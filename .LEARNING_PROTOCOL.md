# Learning & Knowledge Base Management

## Objective
This kill file establishes a protocol for capturing and organizing knowledge gained during development interactions, ensuring reusable insights and patterns are preserved for future sessions.

## Core Principle
**Every discovery, pattern, solution, or lesson learned that could benefit future interactions must be documented in appropriate skill files.**

## What to Capture
1. **Technical Patterns**: Recurring solutions, best practices, workarounds
2. **API Integrations**: Working examples with tokens, authentication flows, error handling
3. **Deployment Strategies**: Successful deployment workflows, configuration patterns
4. **Error Solutions**: Common errors, root causes, and proven fixes
5. **Tool Integration**: How tools interact, command sequences, configuration requirements
6. **Project-Specific Knowledge**: Architecture decisions, naming conventions, build processes

## Storage Locations

### Workspace-Scoped (`/memories/repo/`)
- Project-specific facts and conventions
- Build commands, project structure
- Verified practices for this codebase
- Example: `railway-graphql-api-patterns.md`

### User-Persistent (`/memories/`)
- Cross-project patterns and insights
- General lessons learned
- Frequently used commands
- Tool integration patterns
- Example: `deployment-patterns.md`, `github-workflows.md`

### Session-Specific (`/memories/session/`)
- In-progress notes
- Task-specific context
- Temporary working state
- Cleared after session ends

## Execution Protocol

### During Development
1. **Identify** learnings as they occur
2. **Document** immediately in temporary notes
3. **Categorize** by scope (workspace, user, session)
4. **Link** to related existing knowledge

### At Session Completion
1. Review all discoveries made
2. Consolidate session notes into permanent files
3. Update relevant skill files
4. Verify no useful knowledge is lost

## Example: Railway GraphQL API Learning

**Discovery**: Railway GraphQL API requires proper JSON encoding for queries
**Learning**: String interpolation in bash causes JSON parsing errors
**Solution**: Use Python for GraphQL requests instead of curl + bash string manipulation
**Captured In**: `/memories/repo/railway-graphql-patterns.md`
**Reusable Pattern**: Template for Railway API interactions

Brief description of the topic

## Key Patterns

- Pattern 2: Description and when to use

## Working Examples
### Example 1: [Use Case]
```[language]
code snippet
```

## Common Pitfalls
- Issue 1: Why it happens and how to avoid
- Issue 2: Why it happens and how to avoid

## References
- Link to documentation
- Related skill files
```

## Integration with Development Workflow

1. **Before Starting**: Review relevant skill files
2. **During Work**: Note discoveries in session memory
3. **On Blockers**: Check `/memories/` for similar solutions
4. **After Solving**: Add to appropriate skill file
5. **End of Session**: Consolidate learnings

## Maintenance

### Weekly Review
- Check for duplicate knowledge across files
- Consolidate related patterns
- Update deprecated solutions

### Cross-References
- Link related skill files
- Maintain index of available knowledge
- Tag with relevant technologies/domains

## Success Criteria
✅ Each session leaves the knowledge base richer
✅ Future sessions start with context from past learnings
✅ Patterns are documented before they're forgotten
✅ No useful solution is discovered twice
